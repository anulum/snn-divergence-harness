# Validation status

The repository foundation is under construction. The current documentation source builds with strict MkDocs validation, and the current source cohort passes native REUSE licence checking. These checks do not qualify repository-wide validation, a model driver, numerical comparison, statistical power, an installed domain package or a benchmark.

The native bootstrap installs or verifies exact selected Actionlint/Gitleaks binary and licence bytes. This file-identity gate does not certify a scan outcome or a reproducible build.

The available local commands are make metadata, make source-provenance, make docs, make licence, make native-tools, make native-tools-check make dependencies, make workflows and make inventory. The metadata command checks its complete source-selected descriptor/schema/lock scope; it does not grant domain acceptance. The documentation and licence commands invoke the project environment’s actual documentation renderer and source-licence checker respectively. The documentation build covers public documentation. Root Markdown links are checked separately; this is not a claim that every future product page or API is rendered.

Metadata and source provenance are implemented project-owned controls. Their dedicated tests exercise real APIs, source files and subprocess commands. The dependency command compares source-selected tooling inputs and actual installed metadata for the complete selected development graph, and retains native-tool file failures. It does not verify every installed payload byte, invoke those tools or perform a vulnerability audit. The documentation command now checks selected configuration before the actual strict native build, then inspects its output against source. Direct read-only inspection does not attest builder execution. Inventory generation and independent complete-tree/Git verification are implemented. The preflight retains actual child outcomes and every unexecuted requirement. The complete native chain and hosted/profile transitions still require their own current qualification. There is no preflight success to inherit from another repository.

Later domain validation must exercise real subject entry points and independently constructed references across every maintained lane. Exact source populations, supported ports, nested outputs, reset and timing semantics remain explicit. Incomplete output, missing references or unestablished joint power cannot become accepted equivalence.

Coverage will enrol every maintained source path from its first implementation. Statement or branch percentages apply only to their reported source cohort and never establish numerical correctness by themselves.

See [validation-tooling status](docs/validation-tooling.md) and [contribution requirements](CONTRIBUTING.md).


The new inventory and orchestration cohort has dedicated public-entry-point tests. A generated inventory does not prove complete-tree acceptance; a focused preflight that runs one successful check still refuses overall acceptance when other required checks are not_run. Every coverage result applies to its explicit owning source/test cohort. The actual source and environment inventory commands have their own scopes: native REUSE source files with checksums and declared licences, plus installed Python packages and versions. Ancillary attribution/configuration and licence text exclusions remain explicit. No descendant-process-cleanup, hosted execution or independent-review result follows from orchestration alone.

Bandit marks the required subprocess imports and native executions for review. Their narrow source annotations name only the import rule and direct-process rule at the necessary lines: commands come from maintained finite vectors, use no shell and never incorporate received program names or argument vectors. The native Git executable is selected at its absolute Linux path. No rule is disabled globally or by a severity threshold; the process boundary and its limitations remain explicit.
