# Components and data boundaries

## Implemented repository foundation

The current executable surface is repository validation tooling. It has no domain distribution, model driver, comparison engine or qualified scientific result. The trusted maintained checkout and selected development environment run the commands below; supplied metadata cannot nominate another executable, schema plugin or acceptance policy.

| Component | Reads and produces | Boundary |
| --- | --- | --- |
| Metadata validation | Fixed descriptor, selected schema and development lock | Checks actual interpreter and source-selected identity/state; does not depend on a generated inventory |
| Source attribution | Bounded public source cohort, native headers, JSON sidecars and selected originals | Source ownership and original-byte identity; no domain verdict |
| Workflow policy | Seven workflow definitions and selected action/tool provenance | Trigger, job, permission and command selection; no hosted execution result |
| Dependency alignment | Source-selected input digests and actual installed metadata | Installed graph alignment; not every payload byte or vulnerability status |
| Documentation | Selected configuration, public Markdown, native API source and rendered HTML | Configuration check precedes strict native build; separate inspection does not attest the builder |
| Inventory | Validated metadata, generated inventory, actual source tree and native Git queries | Generation is acyclic; independent verification checks required paths, configuration and publication boundaries |
| Preflight | Maintained command plan and actual child reports/exits | Retains every failed, unavailable or unexecuted requirement; partial selection cannot clear full acceptance |

Metadata validation admits the descriptor before inventory generation. Generation creates an exclusive new output and has no complete-tree prerequisite. Verification reads the completed tree and inventory. Full preflight requires that verification, every other control and the native quality commands; generation alone cannot bootstrap complete acceptance.

Shared local helpers own controlled diagnostics and selected path/configuration policy, actual tree inspection and native Git readback. Workflow helpers own YAML admission and source-selected job/action rules. Documentation helpers separate policy from HTML inspection. Native bootstrap installs only selected executable/licence files from verified archives; verification is read-only.

Make targets and local hooks use the selected tooling environment. Prepared CI invokes the same maintained command surfaces. Full tests and default preflight run in CI or a reserved pre-push environment. Focused preflight retains omitted requirements as not_run. The current local lifecycle requires main and no remote; hosted activation must introduce and verify the corresponding lifecycle policy before prepared workflows can qualify a hosted checkout.

Source secret inspection and source SPDX generation use a temporary projection of the explicit public cohort. Native REUSE receives an explicit project root, avoiding ancestor repository discovery. Environment CycloneDX describes installed packages separately. Source checksums, package metadata alignment, scanner results and numerical correctness are different evidence.

[Validation tooling](validation-tooling.md) documents actual commands, limits, result meanings and native APIs. [Data and authority boundaries](THREAT_MODEL.md) explains what these controls trust and what they do not establish.

## Planned domain components

| Planned component | Responsibility | Required boundary evidence |
| --- | --- | --- |
| Plan and store | Freeze complete input, model, source, environment, method and output selection; retain every attempt | Exact-byte identities and honest complete, partial, failed and refused records |
| Driver adapters | Invoke supported public framework and backend interfaces in their real environments | Actual supported ports, state, reset, timing and output semantics |
| Execution engine | Apply the frozen plan, bounded resources and attempt accounting | Reproducible public subject invocation and complete output custody |
| Comparison methods | Apply the selected discrete, floating or statistical contract | Independent numerical references, complete populations and justified decision rules |
| Reducer and replay | Minimise within the admitted domain while preserving the finding | Fresh replay with preserved preconditions and original method |
| Inspection and verification | Explain the result and separately check source, method and evidence | Complete Toolkit report plus the harness-specific result |
| Consumers | Supply located diagnostics to downstream tools and user interfaces | Real installed producer and consumer integration |

Planned public operations are run, reduce, verify and inspect. Their exact typed inputs, result shapes, refusal reasons and CLI precedence must be selected and exercised with implementation. No empty package or command currently advertises these operations.

The seven prospective external environments are snnTorch, Norse, Sinabs, Rockpool, Spyx, Lava and Nengo. Each driver must retain its supported scope and actual dependency constraints; a missing environment is unavailable, not a passing lane.

Source and schema candidates require an explicit selected version. An input cannot select a more permissive schema or comparison method. Whole statistical family power cannot be inferred from marginal power alone. Publication and hardware control are outside a comparison result's authority.
